What This Project Is

A personal skill library management system that exposes domain expertise to Claude Desktop via MCP. You author skills as structured Markdown files (SKILL.md), register them in a central JSON registry, and a FastMCP server surfaces them to Claude as searchable, loadable tools. When Claude encounters a question matching a domain, it calls search_skills() → get_skill() to load the relevant methodology, then applies it.

SKILL.md FILES
Authored Markdown with YAML frontmatter. Hierarchical: orchestrators → directors → knowledge/action.
REGISTRY.JSON
Central index of all 194 skills. Stores metadata, metrics, health, dependencies, scores, and network topology.
MCP SERVER
FastMCP Python server exposes 7 tools to Claude Desktop. Reloads registry on every call — zero restart needed.

MCP Server Tools

list_skills(domain?, type?, subdomain?)
Browse all skills with optional filters. Returns names, types, descriptions, health, scores. Also lists available domains/subdomains.
search_skills(query)
Keyword search across names, descriptions, and tags. Logs zero/thin results to gaps.jsonl for coverage tracking.
get_skill(name, include_references?)
Read full SKILL.md + reference docs + agent definitions. Logs usage. Three-tier path resolution (relative → absolute → search).
get_skill_details(name)
Metadata only (no file reads). Returns health, score, tags, dependencies, metrics. Fast preview before deciding to load.
get_system_overview()
Bird's-eye library health. Per-domain maturity, gaps, orphan detection, broken references, recommendations. ⚠ Misses sommelier (bug)
record_skill_feedback(name, rating, note?)
Rate 1-5 with optional note. Appends to feedback.jsonl with file locking. Feeds recalibrate_scores.py.
get_skill_stats(skill_name?)
Usage analytics — most/least used skills, never-used detection, feedback averages, gap queries. Per-skill: first use, last use, 7-day repeat count.

Issues & Fixes

sommelier missing from network.domains
registry.json's network.domains object contains 10 domains but is missing sommelier. This means get_system_overview() never reports on 36 sommelier skills — the entire domain is invisible to the library health check. The skills are registered in registry.skills but not wired into the network topology.

Root cause: The sommelier domain was added after the network topology was last built. sync-registry.py adds skills to the skills map but doesn't update network.domains.
python3 scripts/sync-registry.py --apply # rebuilds network.domains
